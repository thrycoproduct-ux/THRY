# Production-Safe Image & LCP Performance Plan

Goal: Fix the ~13 MB image waste and ~350 ms CSS blocking from PageSpeed (https://pagespeed.web.dev/analysis/https-thryco-com/qhavk0n8gs?form_factor=mobile) WITHOUT breaking checkout, admin uploads, cart, or existing product pages.

---

## Principles (non-negotiable)

| Rule | Why |
|------|-----|
| No big-bang deploy | Ship in small PRs, one concern per deploy |
| Feature flags / env toggles | New image delivery can be turned off instantly |
| Never delete old R2 files until verified | Keep originals during migration |
| Validate on preview + production smoke | Every phase has a checklist before merge |
| CrUX lags 28 days | Lab scores improve first; real-user PSI updates later |

---

## What's Actually Broken (root cause)

Upload (admin)     -> often WebP ~650KB OK (new uploads)
Storefront display -> serves FULL R2 file, unoptimized X
Legacy R2 objects  -> many are huge PNGs (~500-800KB each) X
Hero LCP           -> full-size CDN image, wrong preload target X
CSS                -> 2 blocking chunks (~350ms) - minor vs images

Biggest win: Fix HOW images are delivered, not re-upload everything first.

## Phase 1 - Safe Delivery Layer (highest ROI, low DB risk)

Problem: StorefrontImage uses unoptimized: true for all CDN URLs -> no srcset, full 500-800 KB files on 240px cards.

Fix (pick one, behind env flag IMAGE_DELIVERY_MODE):

### Option A - CDN resize helper (recommended)
- Add cdnImageUrl(key, { width, quality, format }) -> media.thryco.com with width/quality params (or Cloudflare Image Resizing if enabled)
- StorefrontImage uses resized URL for display; original key in DB unchanged
- Card: w=400, hero: w=1200, PDP: w=800

### Option B - Fix Next.js /_next/image on Vercel
- Narrow shouldBypassImageOptimization() to SVGs only
- Let sizes + srcset work for R2 URLs already in remotePatterns

Files touched (small):
- StorefrontImage.tsx, utils.ts (or new cdn-image.ts)
- Product card / hero sizes props (already exist - start working)

Validate before merge:
- [ ] Homepage loads, hero visible
- [ ] Shop grid images load
- [ ] PDP main image + thumbnails
- [ ] Cart / checkout unchanged
- [ ] Admin media library preview unchanged
- [ ] Network tab: card images < 80 KB (not 500+ KB)
- [ ] No broken images (404 on CDN)
- [ ] Lighthouse LCP improves on lab test

Rollback: Set IMAGE_DELIVERY_MODE=legacy -> instant revert to current behavior

Expected impact: LCP -0.5 to -1.5s on mobile lab; biggest PageSpeed win

## Phase 2 - LCP Hero Tuning (tiny, safe PR)

Problem: Preload targets first category image, not hero; hero may not have fetchpriority="high".

Fix:
- Preload first hero slide URL (with Phase 1 resize width)
- Hero: priority + fetchPriority="high", NO loading="lazy"
- Remove fetchpriority="high" from below-fold product cards

Validate:
- [ ] Hero paints first on slow 3G throttle
- [ ] PageSpeed "LCP request discovery" warning cleared or reduced
- [ ] No layout shift on hero (CLS stays ~0.01)

Rollback: Revert one file (page.tsx + hero component)

---

## Phase 3 - Upload Hardening (new uploads only)

Problem: Bulk draft upload and some paths skip client WebP compression -> new huge PNGs can still land in R2.

Fix:
- Run compressImageForUpload() in bulk draft path
- Reject or warn if uploaded file sniff != declared type
- Admin UI shows post-compression size before save

Validate:
- [ ] Upload new product image in admin -> R2 object is WebP, < 1 MB
- [ ] Bulk draft upload still works
- [ ] Existing products unchanged

Rollback: Revert upload path only; existing R2 objects untouched

---

## Phase 4 - Legacy R2 Backfill (controlled migration)

Problem: ~13 MB of existing PNGs in R2 - upload fixes don't repair old inventory.

Approach:
1. New script backfill-r2-images.mjs (modeled on upload-saree-model-images.ts)
2. Dry-run first -> log what would change
3. Batch by priority:
   - Batch 1: hero banners (5-10 images)
   - Batch 2: featured / homepage products (~20)
   - Batch 3: full catalog (nightly batches of 50-100)
4. Per image: fetch -> sharp resize/WebP -> new key -> update medias.key + refs -> verify CDN -> delete old key

Safety:
- --dry-run default
- Keep old key for 7 days (soft delete list)
- Per-batch storefront cache revalidate
- Stop on any 404 / DB mismatch

Validate per batch:
- [ ] Random 10 products: images load on shop + PDP
- [ ] Admin media library shows correct thumbnails
- [ ] Order emails / OG images still work
- [ ] No 404s in Sentry/logs for media.thryco.com

Rollback: Point medias.key back to old keys from backup CSV

## What We Will NOT Do (production risk)

| Don't | Why |
|-------|-----|
| Mass-delete R2 objects in one go | Broken images everywhere |
| Change all medias.key without verify step | 404s on live site |
| Enable /_next/image on Cloudflare Workers path without testing | Known attachment-header issues |
| Re-upload entire catalog manually | Slow, error-prone |
| Touch checkout / payment / cart code in same PR as images | Unrelated regression risk |

## Technical Context (codebase)

Upload pipeline:
- Admin browser: canvas resize (max 1600px) + WebP encode (~650 KB target)
- Server processUpload.ts: pass-through validation only, no sharp on Workers
- Bulk draft upload: may skip compression - can land large PNG/JPEG in R2
- R2 key format: uploads/upload-{nanoid}.{ext}

Storefront delivery:
- shouldBypassImageOptimization() forces unoptimized: true on all https:// CDN URLs
- No /_next/image proxy, no srcset for CDN images
- sizes prop exists in components but has no effect while unoptimized
- media.thryco.com / R2 serves raw stored bytes

Key files:
- src/lib/admin/client-image-upload.ts
- src/lib/image/processUpload.ts
- src/components/media/StorefrontImage.tsx
- src/lib/utils.ts (keytoUrl, shouldBypassImageOptimization)
- src/app/(store)/page.tsx (homepage preload)
- src/features/storefront/components/HomeHeroCarousel.tsx
- src/features/products/components/ProductCard.tsx
- scripts/upload-saree-model-images.ts (template for backfill)

Recent INP/cart work (deployed) may take 2-4+ weeks to appear in CrUX PageSpeed scores.
